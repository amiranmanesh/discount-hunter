دو راه استفاده

تخفیف‌ها

فید بی‌پایان همهٔ پیشنهادهای کمپینی محدوده‌ات از هر دو پلتفرم، بیشترین تخفیف اول. چیزی برای تایپ کردن نیست — اسکرول کن.

جستجو

یک کالا، قیمت‌گذاری‌شده در همهٔ فروشگاه‌هایی که به تو ارسال دارند؛ مرتب بر اساس تخفیف، بعد فروشگاه‌های پرو، بعد هزینهٔ ارسال.

چرا قیمتی که می‌بینی واقعی است

سه قانون، که هرکدام چون یک بار اشتباه شد وجود دارند.

قفسهٔ «ویژه خرید اول» خوانده نمی‌شود

هر تخفیف ۹۰ تا ۹۹ درصدی در فید کمپین مخصوص حساب تازه‌ساخته است. اندازه‌گیری شد: ۱۱۹ ردیف new_user که هیچ‌کدام برای حساب قدیمی وجود ندارند. آن باکت اصلاً گرفته نمی‌شود.

نتایج با قفسهٔ خود فروشگاه تأیید می‌شوند

کمپین می‌گفت کوکاکولا زیرو ۳۹٬۰۷۲؛ قفسهٔ همان فروشگاه ۱۱۲٬۳۳۲ بود. حالا هر نتیجهٔ جستجو قبل از نمایش با توکن خودت تأیید می‌شود.

حالت مهمان وجود ندارد

مهمان کمپین دیگری با قیمت دیگری می‌بیند. بدون نشست اسنپ‌مارکت تو، جستجو اجرا نمی‌شود.

نصب

یک دستور، بدون وابستگی جانبی:

docker run -d -p 4173:4173 \
  ghcr.io/amiranmanesh/discount-hunter:latest

بعد http://localhost:4173 را باز کن. روی موبایل با آدرس همان شبکه بازش کن و «افزودن به صفحهٔ اصلی» بزن تا مثل یک اپ مستقل نصب شود.

چرا سرور لازم دارد؟ هیچ‌کدام از دو پلتفرم درخواست cross-origin از مرورگر را قبول نمی‌کنند — اسنپ‌مارکت Access-Control-Allow-Origin را فقط برای دامنهٔ خودش می‌فرستد و دیجی‌کالا جت اصلاً نمی‌فرستد. پس برنامه همراه یک پروکسی سادهٔ هم‌مبدأ سرو می‌شود. پروکسی چیزی نگه نمی‌دارد، ولی سر راه است — برای همین خودت هاستش کن.

ساخته‌شده با

رابط React 19، Vite 8، TypeScript، TanStack Query، zustand
PWA نصب‌شدنی، RTL، تم روشن و تیره، از ۳۹۰ پیکسل تا لپ‌تاپ
سرور Node 22، بدون وابستگی اجرایی — فقط ماژول‌های داخلی
انتشار ایمیج amd64 و arm64 روی GHCR در هر push به main

دربارهٔ پروژه

پروژه‌ای مستقل و متن‌باز با مجوز MIT. از همان APIهای عمومی‌ای استفاده می‌کند که وب‌اپ اسنپ‌مارکت و دیجی‌کالا جت در مرورگر خودت صدا می‌زنند، با حساب و آدرس خودت. سفارشی ثبت نمی‌کند و به سبد خریدت دست نمی‌زند. هیچ وابستگی، تأیید یا ارتباطی با اسنپ یا دیجی‌کالا ندارد.
